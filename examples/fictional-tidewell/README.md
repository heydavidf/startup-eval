# Fictional Tidewell example

Everything here is invented. Tidewell, its founders, the coastal region, the harbour sensor programme, the boat registry, the comparables, and every number are fictional. The four source URLs point at `example.com`, a reserved domain with no content. The verdict illustrates the output format; it is not a finding about any real company.

This folder is a complete run directory in the shape the skill produces:

- `working/inputs/tidewell-pitch-deck.pdf`: a synthetic three-page deck, generated by `build_example.py`.
- `source-brief.md`: page summary and draft claim register.
- `run-manifest.json`: the canonical record of claims, verdicts, sources, scores, agents, and one recorded agent failure.
- `dashboard.html`: the self-contained dashboard rendered from the manifest. Open it in a browser; use the Simple and Advanced buttons or press `A`.
- `report.md`, `claim-register.md`, `evidence-register.md`: the prose artifacts written from the manifest.

The example deliberately includes one refuted market claim, one unverified claim from a failed skeptic agent, and one claim left out of formal verification, so you can see how the method keeps all of them visible.

## Rebuild it

From the repository root:

```sh
python3 examples/fictional-tidewell/build_example.py
python3 scripts/validate_evaluation.py examples/fictional-tidewell
```

The first command regenerates the PDF and the dashboard byte-for-byte. The second should print `VALIDATION PASSED`. To exercise the full script pipeline against a scratch library, see the README at the repository root.

## Use it as a starting point

To run the skill on this fiction, give your agent the deck in `working/inputs/`, ask it to use `startup-eval`, and tell it that web research must stay inside the fiction (it will not find the example.com sources, so expect most claims to come back `uncertain` or `unverified`). For a real evaluation, supply a real deck and let the agent collect dated public sources.
